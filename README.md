# recipes.stewartplatt.com

Stewart Platt's recipe sub-site.

A static site: hand-authored Markdown+YAML-frontmatter recipes, validated
with [zod](https://zod.dev), rendered server-side with
[Preact](https://preactjs.com) + `preact-render-to-string`, and shipped as
plain HTML/CSS/JS with no server at runtime. There's no scaffolder/CMS —
recipes are authored by hand by copying a template file (see "Adding a
recipe" below).

The build is a small hand-rolled Node script (`build/index.ts`, run via
`tsx`), not a framework: it reads every `content/recipes/*.md` file, parses
and validates it, and renders each page with `preact-render-to-string`. Vite
is used alongside it for the dev server, the client-side hydration bundle,
and running tests via Vitest — but production HTML is generated by the
build script, not by Vite's SSR.

This repo is normally worked on as a submodule of the
[websites](https://gitlab.com/shteou/websites) monorepo, which builds it and
deploys the static output to Cloudflare Pages via `deploy/deploy.py` — see
that repo's README for details.

## Directory layout

- `content/recipes/` — recipe content: one Markdown file per recipe, YAML
  frontmatter + a Markdown body. `_template.md` is a fully-commented
  reference copy, excluded from the build by its `_` prefix.
- `src/core/` — pure logic with no rendering concerns: the recipe schema and
  validation (`schema.ts`), the tag taxonomy (`taxonomy.ts`), and the
  scaling/substitution/unit-conversion/step-token logic composed together by
  `present.ts`.
- `src/view/` — Preact components that render a `RecipeViewModel` (from
  `present.ts`) to HTML.
- `src/client/` — browser-side hydration: wires up the interactive bits
  (servings stepper, substitution toggles, unit/steps-view switchers) on top
  of the server-rendered HTML.
- `build/` — the SSR build script (`index.ts`) that ties it all together:
  load + validate content, render every page, copy styles/flags.
- `tests/` — Vitest unit tests (`npm test`) plus a slower build smoke test
  (`npm run test:build`) that runs the real build and checks its output.

## Adding a recipe

Copy `content/recipes/_template.md` to a new file under `content/recipes/`
and fill it in — every field is commented inline with what it does and
whether it's required. See `AGENTS.md` for the tagging and steps
conventions. Once written, run `npm test` and `npm run typecheck` to
validate it (or `npm run build`, which validates every recipe as a
side-effect of generating pages).
